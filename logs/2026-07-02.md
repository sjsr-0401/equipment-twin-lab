## Goal 038: ALD Fault Matrix Report

### 시작 이유

- 사용자가 현재 Unity screenshot 품질이 녹화할 만큼 좋지 않다고 판단했다.

### 구현한 것

- `process batch` CLI mode를 추가했다.
- 정상 공정은 `PASS`를 기대한다.
- recipe에 정의된 모든 fault scenario는 `FAIL`을 기대한다.
- 기대 결과와 실제 결과가 모두 맞으면 CLI exit code `0`을 반환한다.
- 하나라도 기대와 다르면 exit code `1`을 반환한다.
- Markdown fault matrix report를 생성한다.
- Core test에 모든 configured fault가 `Alarmed`로 가는지 확인하는 test를 추가했다.
- CI에서 `process batch` 명령을 실행하도록 추가했다.

### 소프트웨어 아키텍처 설명

이번 구조의 핵심은 `MolyAldRunner`를 계속 source of truth로 유지하는 것이다.

```text
process run
    -> MolyAldRunner 1회 실행

process batch
    -> MolyAldRunner 정상 1회 실행
    -> MolyAldRunner fault 개수만큼 반복 실행
    -> 기대 PASS/FAIL 비교
```

`process batch` 안에 별도 공정 로직을 만들지 않았다.
그래야 나중에 공정 step이 바뀌어도 `MolyAldRunner`만 고치면 단일 실행과 batch 실행이 같이 맞춰진다.

### 사용자가 이해해야 할 것

- `process run`은 한 케이스를 실행한다.
- `process batch`는 정상 + 모든 fault를 한 번에 검증한다.
- fault가 `FAIL`인 것은 나쁜 게 아니다.
- fault scenario에서는 실패해야 맞다.
- 중요한 것은 실패했을 때 `Alarmed`로 안전하게 멈추고 실패 step을 기록하는 것이다.


대신 report를 만드는 명령과 설명 문서를 Git에 올린다.

## Goal 042: HMI Typography and Instrument Panel

### 시작 이유

- 디자인 리뷰에서 "숫자가 죽은 텍스트"라는 지적이 있었다.
- 산업 HMI는 예쁜 화면보다 현재 상태를 빠르게 판독하는 것이 중요하다.
- 버튼 기능을 붙이기 전에 Pressure/Temp/Film을 정상 범위와 함께 읽히는 계기판으로 바꾸는 것이 우선이라고 판단했다.

### 구현한 것

- `MolyAldOperatorCanvas`의 오른쪽 패널을 HMI 정보 위계 기준으로 재정리했다.
- title을 `MOLY ALD HMI`로 바꾸고 run/interlock state strip을 추가했다.
- START/STOP/FAULT/RESET 색상 체계를 더 명확하게 바꿨다.
- Pressure/Temp/Film을 instrument row로 분리했다.
  - 값+단위 readout
  - OK/TARGET 같은 status
  - 정상 범위 band
  - 현재값 fill
- Alarm card에 priority와 synthetic fault code 영역을 추가했다.
