# 2026-07-03 작업 로그

## Goal 049: Fault Scenario Selector UI

오늘 작업은 Unity HMI에서 fault scenario를 직접 선택할 수 있게 만드는 것이다.

### 구현한 것

- `MolyAldProcessPlayer`에 public fault scenario catalog API를 추가했다.
  - `PublicFaultScenarioCount`
  - `SelectedFaultScenarioIndex`
  - `GetPublicFaultScenarioName(int)`
  - `SelectFaultScenarioByIndex(int)`
  - `SelectPreviousFaultScenario()`
- `MolyAldOperatorCanvas`에 `FAULT SCENARIO SELECTOR` 카드를 추가했다.
- HMI에 4개 fault 선택 chip을 추가했다.
  - `PUMP TIMEOUT`
  - `TEMP UNSTABLE`
  - `PRECURSOR TIMEOUT`
  - `PURGE TIMEOUT`
- chip 클릭 시 `SelectFaultScenarioForOperator(index)`가 실행되고, player의 선택값이 바뀐다.
- fault replay가 활성화된 동안에는 scenario 변경을 막았다.
- 선택/차단 이벤트를 operator action log에 남기게 했다.
- Unity smoke test에 selector 검증을 추가했다.

### 소프트웨어 구조 설명

이번 구조는 UI가 직접 fault JSON 파일을 읽지 않게 만든 것이 핵심이다.

```text
HMI chip
  -> MolyAldOperatorCanvas.SelectFaultScenarioForOperator(index)
  -> MolyAldProcessPlayer.SelectFaultScenarioByIndex(index)
  -> selectedFaultScenarioName
  -> FAULT REPLAY
  -> ActivateSelectedFaultScenario()
  -> StreamingAssets/faults/moly-ald-timeline.{scenario}.json
```

즉, Canvas는 operator interaction만 담당하고, 실제 replay timeline 선택/검증은 `MolyAldProcessPlayer`가 담당한다. 이 분리를 지켜야 나중에 WPF, Web HMI, Unity 3D HMI로 바뀌어도 process replay 로직을 재사용할 수 있다.

### 왜 active fault 중 scenario 변경을 막았나

고장 알람이 떠 있는 상태에서 selector만 바뀌면 화면에 모순이 생긴다.

- 알람은 `precursor-dose-timeout`
- selector는 `pumpdown-timeout`
- replay timeline은 아직 precursor fault

이런 상태는 실제 장비 HMI에서 위험한 UI다. 그래서 fault가 활성화되면 selector는 보이지만 변경은 막고, `RESET` 후 다시 선택하게 했다.
