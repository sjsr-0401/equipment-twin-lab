# Goal 049: Fault Scenario Selector UI

Date: 2026-07-03
Branch: `goal/049-fault-scenario-selector-ui`

## Objective

Make the Unity HMI let an operator choose which public ALD fault scenario to replay before pressing the fault command.

Before this goal, Unity could replay fault timelines, but the selected scenario was mostly hidden behind code/default state. This made the demo look less like an operator console. The goal was to expose that choice directly in the HMI.

## Implemented

- Added public fault scenario catalog accessors to `MolyAldProcessPlayer`.
  - `PublicFaultScenarioCount`
  - `FaultScenarioCount`
  - `SelectedFaultScenarioIndex`
  - `GetPublicFaultScenarioName(int)`
  - `SelectFaultScenarioByIndex(int)`
  - `SelectPreviousFaultScenario()`
- Added a `FAULT SCENARIO SELECTOR` card to the Unity canvas HMI.
- Added four selectable HMI chips:
  - `PUMP TIMEOUT`
  - `TEMP UNSTABLE`
  - `PRECURSOR TIMEOUT`
  - `PURGE TIMEOUT`
- Added operator action logging for scenario selection.
- Locked scenario changes while a fault replay alarm is active.
- Updated the fault command label to show `FAULT REPLAY`.
- Extended Unity smoke-test validation so selector behavior is automatically checked.

## Architecture

```text
Operator chip click
  -> MolyAldOperatorCanvas.SelectFaultScenarioForOperator(index)
  -> MolyAldProcessPlayer.SelectFaultScenarioByIndex(index)
  -> player.SelectedFaultScenarioName
  -> FAULT REPLAY button
  -> MolyAldProcessPlayer.ActivateSelectedFaultScenario()
  -> StreamingAssets/faults/moly-ald-timeline.{scenario}.json
  -> failed process step displayed on HMI
```

The important software boundary remains the same: Unity is not inventing the process failure. Unity selects and displays a replay timeline generated by the Core/CLI process model.

## Operator behavior

- When no fault is active, the operator can change the selected scenario.
- When a replay fault is active, scenario chips remain visible but changing selection is blocked.
- The operator must press `RESET` before choosing a different fault scenario.

This avoids an HMI inconsistency where the alarm says one scenario is active while the selector silently switches to another.

## Notes for future maintenance

If a new fault scenario is added, update the Core/CLI process fault catalog and generate the matching timeline JSON first. The Unity HMI selector should then expose it by extending `PublicFaultScenarioNames` and, if needed, adding a short display label in `FaultScenarioChipLabel`.
